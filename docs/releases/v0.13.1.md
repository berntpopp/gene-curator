# v0.13.1

Deployment release: Gene Curator now ships as published, digest-pinnable images and runs
behind a reverse proxy without host-side scripts. No application behaviour changes.

Merged: [#628](https://github.com/berntpopp/gene-curator/pull/628).

## Highlights

- **Published images.** Tags `vX.Y.Z` publish `ghcr.io/berntpopp/gene-curator/{backend,frontend,migrate}`
  with provenance and an SBOM (`.github/workflows/docker.yml`).
- **One-shot migrate image.** `database/Dockerfile` applies `database/sql` with the same
  `schema_migrations` bookkeeping as `make db-migrate` (both run `database/migrate.sh`).
- **NPM overlay.** `docker/docker-compose.npm.yml`: no host ports, frontend on `npm_default`,
  backend and database on an internal network with an explicit subnet (`10.251.10.0/24`),
  read-only containers, dropped capabilities, resource limits, external data volume.
- **Same-origin API.** The published web image calls `/api/v1` on its own origin; its nginx
  forwards `/api`, `/mcp` and the MCP OAuth endpoints (`POST /register` only, so the SPA's
  `/register` page keeps working) to the backend and passes the real client address on.
- **No seeded logins in production.** The `admin123` accounts and the `test_user` role moved to
  `database/fixtures/` (dev and test databases only). Create the first admin with
  `backend/scripts/create_default_user.py` (`ADMIN_EMAIL`, `ADMIN_PASSWORD`).
- **Strong `SECRET_KEY`.** With `ENVIRONMENT=production` the API refuses a key shorter than
  32 characters or a placeholder.

## Upgrading

Existing databases are unaffected: 004 and 006 are already recorded in `schema_migrations`, so
the seeded dev accounts stay where they exist. Disable them by hand on any shared instance.
New deployments: see README, *Production deployment*.
