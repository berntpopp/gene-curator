# v0.10.0

Wave 8 release: OAuth 2.1 sign-in for MCP clients, the LLM second view (skeptic and advocate),
split disease entities per gene, leaner MCP output, score recompute for every engine, and the
UI items left open in v0.9.0.

Every item cites a merged PR, checked against `gh pr view` and the merged code on 2026-10-30
(merged since v0.9.0: #524–#529, #536, #537, #540, #541, #543).

## Highlights

- **MCP OAuth 2.1 with dynamic client registration.** Claude Code and other MCP OAuth clients
  register themselves (RFC 7591), discover the server (RFC 8414, RFC 9728) and sign in through a
  consent page at `/oauth/consent`; only the authorization code flow with PKCE S256 is served.
  An access token is a personal access token row (1 h) with a rotating refresh token (30 days,
  sliding), so RLS, scope roles, the 4-eyes rule, the account-operation block, rate limits and
  the MCP audit channel apply unchanged. Each connection shows under Access tokens as
  `OAuth: <client name>`; revoking it ends the connection. Personal access tokens keep working.
  Migration 064. [#528](https://github.com/berntpopp/gene-curator/pull/528)
- **LLM second view.** A blind skeptic and a blind advocate review a curation without its
  computed scores, class, rationale or preliminary verdict. Only cited findings are kept; the
  proposed evidence is scored by the curation's own engine and methodology version, and the UI
  (`/scopes/:scopeId/curations/:curationId/second-view`) shows disagreements first. It is
  advisory only: tests assert the curation, scores, state, `lock_version` and reviews stay
  unchanged. Reviewers accept or dismiss findings; curators cannot decide on their own
  curation. Migration 065.
  [#529](https://github.com/berntpopp/gene-curator/pull/529),
  [#536](https://github.com/berntpopp/gene-curator/pull/536),
  [#541](https://github.com/berntpopp/gene-curator/pull/541)
- **Split disease entities per gene (#530).** The unit of curation is the gene-disease-MOI
  entity: `entity_key` (MONDO id | MOI, `''` without a MONDO id) keys the one-active,
  one-open and open-draft indexes. Each approval opens its own draft, activation supersedes only
  its own entity, and `''` still covers the whole gene. Catalogue agreement and consensus are
  computed per entity; the gene page, palette and curation form show and ask for the entity.
  Migration 067. [#537](https://github.com/berntpopp/gene-curator/pull/537),
  [#541](https://github.com/berntpopp/gene-curator/pull/541)
- **Leaner MCP output.** `get_curation` on `/mcp` omits `evidence_data` (an `omitted` note says
  how to get it) and takes `fields=` for named keys or dotted paths; long changed strings in
  `curation_diff` and `read_curation_for_review` come as `word_diff`; precuration writes no
  longer echo `evidence_data`. REST is unchanged.
  [#526](https://github.com/berntpopp/gene-curator/pull/526)
- **Score recompute for every engine.** `make recompute-scores` now scores GenCC and qualitative
  curations through their engine, as saves do, and no longer rewrites a curation whose only
  change is warning text. Out-of-range and non-finite rows score 0 and stay listed in the trace.
  [#527](https://github.com/berntpopp/gene-curator/pull/527)
- **Admin direct add.** Scope and platform admins can add a member without an invitation from
  the invite dialog. [#525](https://github.com/berntpopp/gene-curator/pull/525)
- **My work and palette.** My work shows Disease (with MOI), Stage and Classification and
  searches disease; the command palette shows each gene's newest visible classification.
  [#525](https://github.com/berntpopp/gene-curator/pull/525),
  [#536](https://github.com/berntpopp/gene-curator/pull/536),
  [#541](https://github.com/berntpopp/gene-curator/pull/541)

## Breaking changes

- **Evidence-item endpoints removed.** The four `/curations/{id}/evidence...` endpoints
  (deprecated in v0.9.0) are gone, with their client methods and generated types. The
  `evidence_items` table stays. Record evidence in `evidence_data`.
  [#527](https://github.com/berntpopp/gene-curator/pull/527)
- **MCP output.** `get_curation` on `/mcp` omits `evidence_data` unless `fields=` asks for it;
  `blocked[].stage` became `blocked[].stages` (one entry per reason) in `get_workflow_state` and
  the review read; precuration writes no longer echo `evidence_data` (read it with
  `get_precuration`). `/mcp/full` keeps the API's shape apart from `fields=`.
  [#526](https://github.com/berntpopp/gene-curator/pull/526)
- **Blocked approval.** When an open curation blocks the curation an approval would create, the
  result has `curation_created: false`, `curation_id` set to the blocking curation and a message
  that says why. [#541](https://github.com/berntpopp/gene-curator/pull/541)
- **Flagged rows score 0.** Out-of-range and non-finite rows count nothing instead of being
  clamped, reversing #434. Active and archived curations with such rows keep their stored
  result until resubmitted. [#527](https://github.com/berntpopp/gene-curator/pull/527)
- **Creating a curation** without `precuration_id` on a gene with several entities returns 422.
  [#537](https://github.com/berntpopp/gene-curator/pull/537)
- **Finding decisions are not on MCP.** `PATCH /llm-findings/{id}` (accept or dismiss) is a
  human reviewer decision and is excluded from the MCP tools.
  [#529](https://github.com/berntpopp/gene-curator/pull/529)

## Fixes

- A log line written from a temporary event loop (sync endpoints that call `asyncio.run`, such
  as precuration save_draft) no longer schedules a database write on the shared asyncpg engine
  from the wrong loop, which crashed uvicorn. The logger hands such writes to the main loop.
  [#540](https://github.com/berntpopp/gene-curator/pull/540)
- Unique entity-index collisions return 409 naming the existing record, not 500: a draft save
  that changes the disease to one the author already has a draft for (`precuration_id`), and a
  racing curation create or approval (`curation_id`).
  [#537](https://github.com/berntpopp/gene-curator/pull/537)
- Database logging works again: `initialize_database_logger` configures the shared logger
  instead of replacing it, so loggers created at import time write to `system_logs`.
  [#543](https://github.com/berntpopp/gene-curator/pull/543)
- A new curation for a gene with several approved precurations asks which entity to curate:
  an open curation of that entity opens, an active one is re-curated, otherwise a draft starts
  for it. The curation detail view (reviewers) and the review queue link to the AI second view.
  The leave prompt fires only after real edits. The approval notice links the blocking curation
  instead of showing its UUID, and the MCP instructions say that `curation_created: false`
  means `curation_id` is the blocking curation.
  [#543](https://github.com/berntpopp/gene-curator/pull/543)
- Migration 066: the own-membership guard keys on `OLD.user_id`, so a removed member who admins
  another scope cannot move and reactivate their own row.
  [#524](https://github.com/berntpopp/gene-curator/pull/524)
- Second view: the prompt gets disease, MONDO and MOI from the nested shape and the
  precuration; one pending run per curation (a per-scope advisory lock also closes the cap race
  for reviewers); the latest run per strategy shows its status and error code.
  [#536](https://github.com/berntpopp/gene-curator/pull/536),
  [#541](https://github.com/berntpopp/gene-curator/pull/541)
- Migration 068 publishes Standard_Precuration v2 and ClinGen_SOP_v11 v3 with the MONDO lookup
  on `mondo_id`; migration 069 publishes a ClinGen Precuration version with XLD = HP:0001423.
  [#536](https://github.com/berntpopp/gene-curator/pull/536),
  [#541](https://github.com/berntpopp/gene-curator/pull/541)
- The Definitive replication hint fires on the ClinGen total >= 12, not genetic >= 12.
  [#527](https://github.com/berntpopp/gene-curator/pull/527)
- Submit is blocked while the score preview has rows that score 0; the score panel names
  out-of-range rows by label with the real reason; a MONDO pick fills `disease_name` in nested
  rows. [#525](https://github.com/berntpopp/gene-curator/pull/525),
  [#536](https://github.com/berntpopp/gene-curator/pull/536)
- A 422 is no longer logged as "Database error", and a 4xx is logged as a warning.
  [#536](https://github.com/berntpopp/gene-curator/pull/536),
  [#541](https://github.com/berntpopp/gene-curator/pull/541)
- `mcp>=1.30.0` floor in `backend/pyproject.toml`; the unused `curator` rate-limit tier is
  removed. [#524](https://github.com/berntpopp/gene-curator/pull/524)

- Tooling: the source file-size limit is 700 lines (was 650), an owner decision; files
  already above 700 stay allowlisted and may only shrink.

## Security

- OAuth: PKCE S256 only; redirect URIs must be HTTPS or loopback; codes, refresh tokens and
  client secrets are stored as sha256 only; registration is bounded (client name 100
  characters, 10 redirect URIs of 2000 characters, 8 KB of metadata, state 512). The consent
  endpoint accepts a session only (a PAT or OAuth token gets 403).
  [#528](https://github.com/berntpopp/gene-curator/pull/528)
- Untrusted data in LLM prompts is delimited, not HTML-escaped, and the delimiter cannot be
  forged: non-ASCII goes as `\uXXXX` escapes and every tag-like `<` is neutralized.
  [#536](https://github.com/berntpopp/gene-curator/pull/536)
- The cross-loop logger crash above could take the API down from a single save.
  [#540](https://github.com/berntpopp/gene-curator/pull/540)

## Upgrading

1. Upgrade older installations through the [v0.9.0 instructions](v0.9.0.md#upgrading) first.
2. Run `make db-migrate` to apply 064–069 in order before restarting the backend:
   `064_mcp_oauth`, `065_llm_second_view`, `066_guard_own_membership_old_user`,
   `067_split_disease_entities`, `068_seeded_mondo_lookup`, `069_clingen_precuration_xld_hpo`.
3. The migration user must be a superuser or have BYPASSRLS: 064 adds SECURITY DEFINER
   functions (`oauth_grant_owner`, `oauth_rotate_refresh_token`).
   [#528](https://github.com/berntpopp/gene-curator/pull/528)
4. Run 067 while nobody is editing: its backfill updates curations, which bumps
   `lock_version`, so open editors get 409 on their next save.
   [#537](https://github.com/berntpopp/gene-curator/pull/537)
5. Set `GENE_CURATOR_PUBLIC_URL` (the API origin, https in production) and
   `GENE_CURATOR_FRONTEND_URL` (the web app origin); `docker-compose.prod.yml` refuses to start
   without them. [#528](https://github.com/berntpopp/gene-curator/pull/528)
6. Claude Code over OAuth: `claude mcp add --transport http gene-curator https://<API host>/mcp`,
   then run `/mcp` in Claude Code and choose Authenticate.
   [#528](https://github.com/berntpopp/gene-curator/pull/528)
7. `make recompute-scores` now covers every engine; GenCC and qualitative verdicts can change.
   [#527](https://github.com/berntpopp/gene-curator/pull/527)

## Known limits

- Rate-limit buckets are per worker, so N workers allow up to N times the configured rate.
  [#524](https://github.com/berntpopp/gene-curator/pull/524)
- Claude.ai custom connectors over OAuth have not been tested against a public URL.
- `asyncio.run` in sync services (`publication_service`, `ontology_service`,
  `gene_verification`) is still present; #540 only makes the logger safe around it.
  [#540](https://github.com/berntpopp/gene-curator/pull/540)
- Model ids for `openai_compatible` providers are not checked for pinning (Anthropic ids must be
  dated or versioned). [#529](https://github.com/berntpopp/gene-curator/pull/529)
- #464 stays open: the second view is not queued automatically on submit.
  [#529](https://github.com/berntpopp/gene-curator/pull/529)

- The entity chooser lists only entities with an approved precuration: a legacy open curation
  with no precuration link does not appear there.
  [#543](https://github.com/berntpopp/gene-curator/pull/543)
