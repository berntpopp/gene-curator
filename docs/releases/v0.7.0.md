# v0.7.0

Wave 5 release: score traces, a ClinGen methodology successor, review and form fixes, and
interface polish. Gate and review history is in the
[Wave 5 report](../../.planning/waves/wave5/WAVE5-REPORT.md).

## Scores and methodology versions

- The editor and saved detail views display the backend score trace: arbitrary sections,
  categories and evidence types, item counts, raw/counted points, effective caps and the
  selected classification rule or override. Client-side scoring and guessed thresholds are
  removed; stale preview responses cannot replace a score after another edit. Missing historical
  traces remain explicitly unavailable. During edits, pending previews retain the score panel and
  checklist layout while hiding stale numeric results. [#446](https://github.com/berntpopp/gene-curator/pull/446)
- Recompute reads each curation's pinned point model, recognizes custom evidence paths and
  reports unsupported non-empty paths instead of silently discarding their existing scores.
  Finite out-of-range contributions retain their values with warnings; non-finite contributions
  are excluded and flagged. PMID warnings distinguish scored evidence from zero-point evidence.
  [#444](https://github.com/berntpopp/gene-curator/pull/444)
- Migration 049 publishes a separate immutable ClinGen successor for eligible unchanged stock
  schemas. Existing published snapshots, pins, evidence and stored scores remain unchanged;
  custom, derived or edited definitions are preserved. The migration is idempotent and allocates
  the next available methodology version. [#450](https://github.com/berntpopp/gene-curator/pull/450)
- In that successor, qualifying AR biallelic evidence starts with suggestions of 3 points for
  two null variants, 1.5 for null plus other, and 0.2 for two other variants. Blank and selector-only
  rows score zero. Any manual score edit, including the same value, stops automatic suggestions;
  loaded rows retain their scores. These are starting suggestions, not a replacement for clinical
  assessment. [#450](https://github.com/berntpopp/gene-curator/pull/450)
- Successor segregation evidence requires explicit curator-entered points, including legacy-shaped
  evidence. New segregation rows leave points unassigned: LOD/count evidence without points
  scores zero with a warning; a deliberate zero is preserved across save/reload.
  Full family/method-aware automatic scoring is deferred to
  [#447](https://github.com/berntpopp/gene-curator/issues/447).
  [#450](https://github.com/berntpopp/gene-curator/pull/450)

## Curation, review and catalogue

- Local recovery checks the authoritative server version before offering a replacement, removes
  only the matching saved/offered snapshot and keeps readonly review evidence authoritative.
  Local drafts remain available for a later authorized edit.
  [#442](https://github.com/berntpopp/gene-curator/pull/442)
- A reviewer who has already approved cannot approve the same round twice, but retains comment
  and request-changes actions. Legacy reviews with zero approvals remaining can still activate;
  the author cannot approve their own work, including administrators.
  [#441](https://github.com/berntpopp/gene-curator/pull/441)
- Frontend and backend share condition semantics, including nested fields and array rows.
  Entering review checks required content from the pinned methodology through dedicated submit,
  direct and bulk transitions. Missing required booleans fail validation; false answers a required boolean and numeric zero
  counts as an answered numeric field. Declared scalar defaults are included in untouched editable-form saves;
  existing values and readonly records are preserved. Readonly disease requirements can use
  legitimate same-gene/same-scope linked precuration data without copying it into evidence. [#445](https://github.com/berntpopp/gene-curator/pull/445)
- PMID requests have bounded concurrency and deadlines. Review entry performs remote lookups
  before write locks, then refreshes and checks permissions and the exact evidence/version/status/pin
  before writing. Bulk operations deduplicate lookups while preserving per-item outcomes. Completed
  not-found results remain blocking even when other lookups time out; transient outages keep the
  existing nonblocking policy. [#449](https://github.com/berntpopp/gene-curator/pull/449)
- Saved PMID checks retry when a readonly table becomes editable. Unrelated score edits and row
  reordering do not retry failed lookups; closing one table does not reset another caller’s result. New-row focus handles schema
  labels safely, and approved-precuration lookup is independent of the current list page/filter.
  [#449](https://github.com/berntpopp/gene-curator/pull/449)
- Catalogue disease filtering/options resolve a curation's own disease or its linked precuration,
  including nested disease definitions. Migration 048 corrects the view's genetic/experimental
  score expressions while retaining its invoker security and stored curation values.
  [#440](https://github.com/berntpopp/gene-curator/pull/440)
- Schema derivation reports the derived result accurately, labels the action consistently and
  handles duplicate names, including concurrent requests, with actionable validation errors.
  [#443](https://github.com/berntpopp/gene-curator/pull/443)

## Interface

- Evidence tables scroll locally, descriptions appear once, and true readonly evidence displays
  selectable values and PMID links rather than input controls. Titles/review-count chips wrap,
  scope-role chips use their theme foreground/background pair, invitation dates use local time,
  and Save/Submit controls stay sticky above navigation.
  [#451](https://github.com/berntpopp/gene-curator/pull/451)
- MONDO suggestions are filtered upstream to descendants of the human-disease branch
  `MONDO:0700096`, before pagination. This excludes animal diseases but also some human susceptibility
  entities outside that branch. Exact canonical ID lookups retain saved labels outside the suggestion branch in the same
  request. Existing IDs are preserved; there is no remapping
  or save-time revalidation. [#451](https://github.com/berntpopp/gene-curator/pull/451)

  [#456](https://github.com/berntpopp/gene-curator/pull/456). Existing password hashes still

## Upgrading

1. Upgrade older installations through the [v0.6.0 instructions](v0.6.0.md#upgrading), including
   their separately required corrections. [#420](https://github.com/berntpopp/gene-curator/pull/420),
   [#423](https://github.com/berntpopp/gene-curator/pull/423)
2. Run `make db-migrate` to apply 048 and 049 before restarting the backend. Both migrations record
   themselves and support repeat application.
   [#440](https://github.com/berntpopp/gene-curator/pull/440),
   [#450](https://github.com/berntpopp/gene-curator/pull/450)
3. Review the newly published ClinGen version before starting new records. Existing records keep
   their original pin; this upgrade does not re-pin or automatically recompute historical records.
   [#450](https://github.com/berntpopp/gene-curator/pull/450)
4. Complete required answers before submitting existing drafts. Hidden conditional fields are not
   required; a visible required boolean must have an answer.
   [#445](https://github.com/berntpopp/gene-curator/pull/445)

## Known limits and scope

- Historical ClinGen v1 automatic segregation heuristics remain unchanged and can over-score some
  inputs; the successor's explicit-points requirement contains that behavior for new pins. Full
  SOP family/method-aware aggregation needs separate work in #447.
  [#450](https://github.com/berntpopp/gene-curator/pull/450)
- Qualitative preview/save parity is not fixed: excluded
  [#386](https://github.com/berntpopp/gene-curator/issues/386) includes persistence dispatching through
  ClinGen regardless of a qualitative pin. The score UI displays the returned result faithfully;
  its verified persistence parity applies to ClinGen/custom point models.
  [#446](https://github.com/berntpopp/gene-curator/pull/446)
- When multiple active workflow pairs share a precuration schema, approval can select the first
  matching pair instead of the scope default; tracked separately as
  [#448](https://github.com/berntpopp/gene-curator/issues/448), observed during
  [#446](https://github.com/berntpopp/gene-curator/pull/446) verification.
- The accepted Wave 4 reductions remain: the implemented scope is the agreed score-trace presentation work,
  not every original proposal under the methodology epic. Excluded workflows, permission
  configuration and dispatch work are not claimed delivered.
  [#446](https://github.com/berntpopp/gene-curator/pull/446)
- The login page ships the seeded development credentials in the production bundle; tracked as
  [#461](https://github.com/berntpopp/gene-curator/issues/461). Do not rely on those accounts
  existing in production, and change or remove them on any deployed database.
