# v0.6.0

Methodology versions (epic #264): curations and precurations are pinned to an immutable, published
version of their methodology, and scoring, forms, validation and the workflow read that version.

## Highlights

- **Methodology versions**: every schema has published, immutable versions; each curation and precuration is pinned to one (migration 042) (#407).
- **One scoring interpreter**: ClinGen SOP v11 is data (a point model) read by one interpreter, replacing hard-coded constants; scores carry a trace (#416, #419).
- **Forms from the pinned version**: curation and precuration forms render and validate from the record's pinned version; the hard-coded ClinGen components are gone (#415, #421).
- **Publish gate**: a version is published only after static checks and the schema's own scoring tests pass (#413, #419).
- **Workflow from the version**: allowed transitions and the number of required reviewers come from the pinned version (#414).
- **ClinGen SOP v11 corrections**: stored scores change for some curations; see Upgrading (#420).

## Methodology versions

- `methodology_versions` table; a database trigger refuses any update or delete of a published row, for every role including the owner. Curations and precurations are pinned by trigger on insert and cannot be re-pinned. Existing schemas get a v1 and existing rows are pinned to it (migration 042) (#407).
- Admin API to publish and list versions of a curation schema; responses expose `methodology_version_id` (#407).
- `TRUNCATE` of `methodology_versions` (and a cascading truncate of `curation_schemas`) is refused (migration 043) (#410).
- Any signed-in user can read a pinned version, so forms can render it; publishing stays admin-only (#412).
- Derive: an admin creates a new inactive schema from a published version; its v1 records `derived_from_version_id` (migration 044) (#412). Schema Management labels this "Derive" (#412).
- Publish and create run the static checks and `scoring_configuration.tests` (`name`, `evidence_data`, `expect` total and class); a failure returns 422 `{message, errors}` and writes no version; creating a schema applies the same gate and returns 400. The stage map must keep `entry`, `precuration` and `review` (#419).
- `GET .../curation-schemas/{id}/versions/{vid}/impact` previews an upgrade: the visible curations pinned to older versions whose total or class would change (#419).

## Scoring

- One point-model interpreter: item points, category caps, `combine: max`, section and total caps, ordered bands with `requires`, and curator-asserted overrides. `ClinGenEngine` keeps only the item adapter; ClinGen constants and per-category calculators are removed. A golden test of 158 cases from the old engine reproduces its totals and verdicts (#416).
- Saves, draft saves, submit and the score preview score with the row's pinned version (#416).
- `GET /curations/{id}/score` returns the trace (#419).
- The curation detail page and approve dialog show the stored score and verdict instead of recalculating in the browser (#417).
- The editor's live score comes from `GET /curations/{id}/score`, refreshed 300 ms after each save; the client-side scorer is deleted (#421).

## Validation

- Seeded list rules (`required_fields`, `conditional_required`, `custom_validators`) are applied; the "'list' object has no attribute 'get'" warning is gone (#413, closes #408).
- One schema validator with a JSON path on each diagnostic. New checks: known transition targets, `reviewers_required` 1 to 5, numeric `point_model` caps and ordered bands, rules naming existing fields, `evidence_table` columns having a type (#413).
- `POST /validation/validate-evidence` accepts `methodology_version_id`; with only `schema_id` it validates against the latest published version, not the working copy. An unknown version returns 404 (#413).
- The hard-coded `clingen` score fallback is removed (#413).

## Workflow

- A stage's allowed transitions come from `workflow_states.<stage>.allowed_transitions` of the pinned version; unknown stages use the default table (migration 045) (#414).
- `workflow_states.review.reviewers_required` (1 to 5): an approval below the count is recorded and the curation stays in review. Distinct approving reviewers count; the author never does, admins included (#414).
- The workflow-transition database trigger is dropped; the engine does its work (migration 045) (#414).
- Precuration submit checks required fields against the pinned version (#414).
- The approve toast follows the API: "Approval recorded; more reviewers must approve" versus "approved and activated" (#418).

## Forms

- `DynamicForm` renders a methodology snapshot directly: field-type registry, steps, `visible_when` and `required_when` conditions, and an accessible `evidence_table` field (#415).
- Curation and precuration forms load the record's pinned version (the latest for a new record) and validate against the same snapshot. PMID lookup, row defaults and the score summary are ported; `components/clingen` is deleted (#421, closes #267).
- A precuration with "Lumping/Splitting Applicable" unchecked can be submitted: required fields hidden by a condition are not required, and an unset checkbox is not missing (#418).
- A re-curation no longer shows disease fields twice in the reviewer's change list, and it links to the approved precuration instead of "Unknown" (#411, closes #409).

## ClinGen v1 correction (SOP v11)

- Migration 046 corrects the ClinGen v1 snapshots and working copies in place (owner decision): evidence definitions match what the forms write (`genetic_evidence` and `experimental_evidence` as objects, the 18 evidence tables and contradictory evidence with current columns, point ranges, PMID pattern), `replicated_over_time` is added for the Definitive band, and the corrected point model is embedded (#420).
- Models and Rescue is one category capped at 4; the case-control total is the sum of single and aggregate analyses, capped at 12; an autosomal recessive proband with another variant can score up to 3 (#420).
- `python -m app.services.recompute_scores` re-scores every curation and logs each whose total or class changes (#420).
- Contradictory evidence forces Disputed only when its Impact is "disputed"; "Note only" and "Review needed" rows, or rows with no Impact, never change the class. Migration 047 updates the ClinGen v1 snapshots (custom models untouched) and syncs the working copy to the corrected v1, so publishing the working copy unchanged keeps the corrected model (#423).

## Editor

- The app footer sits at the bottom of short pages (#422).
- Far fewer validation warnings are shown, as one compact collapsible card (#422).
- A live score panel updates while typing (#422).
- A scored row without a PMID shows a warning (#422).
- Escape in form fields, table cells and selects no longer discards the form (#425).
- An unknown PMID blocks Submit with the reason next to the button; drafts still save (#425).

## Decisions

- Language and parser for rules (#269) was shrunk to static checks and the publish gate (#413, #419).
- Upstream diff and pull for derived schemas (#271) was shrunk to the `derived_from` pointer and Derive (#412).
- The expert-panel stage, assign and re-curate effects, `when` expressions, a configurable not-author gate and stage renaming are not in this release (#414).

## Upgrading

- **Run `make db-migrate`** (migrations 042 to 047) before restarting the backend.
- **Then run once**: `make recompute-scores`. It logs every curation whose total or class changes because of the SOP v11 corrections (Models and Rescue cap 4, case-control summed cap 12, AR other-variant proband up to 3) (#420) and the contradictory-evidence rule (#423); custom point models are untouched, and curations pinned to a non-ClinGen methodology are skipped.
- Old contradictory-evidence rows with no Impact no longer dispute a curation; re-label any that really dispute (#423).
- Published methodology versions cannot be edited; to change a methodology, publish a new version or derive a schema (#407, #412).
- **API change**: `POST .../curation-schemas` and publish return an error when the static checks or scoring tests fail (400 on create, 422 on publish) (#419).
- Coming from v0.4.x: follow the v0.5.0 and v0.4.0 upgrade notes first.
