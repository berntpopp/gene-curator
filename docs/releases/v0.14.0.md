# v0.14.0

AI curation pipeline (#639) and two MCP fixes (#640). Human scopes behave as before.

Merged since v0.13.4: [#642](https://github.com/berntpopp/gene-curator/pull/642),
[#643](https://github.com/berntpopp/gene-curator/pull/643).

## Highlights

- **Agent accounts (#639).** `users.is_agent`. An agent account signs in only with a token (a
  platform admin issues it: `POST /api/v1/users/{user_id}/tokens`, signed in), is never a
  platform admin and never manages a scope or its members. The UI marks it *Agent*.
- **Per-scope `review_policy` (#639).**
  - `human`: the default for every scope, existing ones included. Agent accounts curate but
    never review or approve (403).
  - `ai`: agent accounts may review and approve; four-eyes still needs another identity.
  - `ai_then_human`: an agent approval is provisional until a person approves the curation.
    Agents may approve precurations here and under `ai`.

  Scope admins set the policy with `PATCH /api/v1/scopes/{scope_id}`.
- **Approval kind in the export (#639).** `GET /api/v1/export/curations` adds two fields:
  - `approval_kind`: `"human"` or `"ai"`.
  - `approval_model`: the agent's model when `approval_kind` is `"ai"`, else `null`.

  Agent reviewers and approvers are `agentType: "software"` contributions. The approval tools
  (`approve_precuration`, `submit_peer_review`, `execute_workflow_transition`) accept the MCP
  `agent` block, which supplies the model. See README, *Running an AI pipeline*.
- **MCP fixes (#640).** A platform admin resolves any scope by name, as `list_scopes` shows
  them. `create_precuration` returns `warnings` when nobody besides its author may review in the
  scope, so the 409 at submit is no surprise.

## Upgrading

Run `make db-migrate` (093, 094) before restarting the backend; production's migrate service
applies them. 094 lets a platform admin create an agent account's token under RLS. 093 adds the columns with human defaults: every scope stays `review_policy = human` and every
approved curation is `approval_kind = human`. It also lets the reviewer guard trigger accept the
approval stamp. No breaking API changes; the export gains two fields.
