# v0.5.0

## Highlights

- **New app shell**: a navy side rail with a scope switcher on desktop, bottom tabs and a page header on phones, work-count badges and a command palette (#339, #351, #355, #361).
- **My work inbox** replaces the Dashboard: one list of what needs you, what waits on others and what is done (#338, #359).
- **Curation workspace**: breadcrumb, stage line, explicit save state, one live score panel and PubMed lookup for PMIDs (#370).
- **Review per evidence item**: reviewers see what changed since the last submission, accept or query each item, and approve through a checklist (#366, #371).
- **Optimistic locking**: a stale save now returns 409 instead of silently overwriting newer work (#385).
- **Reviewers can review under RLS**: scope reviewers could not approve or request changes on PostgreSQL; fixed by migration 038 (#388).

## Redesign

- Side rail (desktop) with logo, scope switcher, My work, Review, Scopes, Genes, an admin group, theme toggle and user menu (#339).
- Phone bottom tabs (My work, Review, Scopes, Genes, Account); the old navigation drawer is gone (#351).
- One `GET /me/work` request feeds the My work and Review badges on rail and tabs; signed-in phones get a white page header with title, search and theme toggle (#361).
- Command palette: Ctrl/Cmd+K, `/` to search, `?` for shortcuts, `G` then `W` for My work; searches genes, curations and scopes through the new `GET /search` (#349, #355).
- Shared `DataTable` with search, filters, column picker and table state in the URL (#341).
- Quieter sign-in, Register and Home pages, plain copy, phone page titles (#337, #368).
- Gene catalogue is a genes x scopes matrix: one column per scope, an agreement column and filter, scope picker, state in the URL (#350, #358).
- Gene page as a case file: one row per scope with classification, disease, inheritance, stage and score, an agreement banner, and external links (HGNC, OMIM, ClinGen, GenCC, PanelApp, gnomAD, PubMed) (#347, #364).
- Scopes: members, settings, create form and scope list reworked (#352); stage strip, genes table on `DataTable`, bulk bar for assignment, priority and due date (#356).
- Paste-a-list gene intake: paste up to 1000 symbols, aliases or HGNC IDs, resolve them (`POST /genes/resolve`), pick among ambiguous matches and add them to the scope in one step; plus a curator workload panel (#348, #362).

## Curation workspace

- Workspace frame with breadcrumb (scope > gene > curation), stage line, save state (Saved / Saving / Unsaved changes / Save failed + Retry), Save draft and Submit in the header, Ctrl/Cmd+S, and a guard for unsaved changes (#370).
- One score panel with the SOP band, category table and a "Before you submit" list; shorter evidence tabs (#370).
- PMID cells look the PMID up on blur and show the citation; an unknown PMID blocks save and submit (#370). Only numeric PMIDs get a PubMed link (#383).
- Evidence points outside the editor's per-table limits are rejected with 422 on create, update and submit (#384).
- After changes are requested, the workspace shows the reviewer's note and open queries (#387).
- Curation JSON schemas carry labelled `enumOptions` for select fields (#357).

## Review

- Per-item review comments (migration 037) with RLS: reviewers query or accept an evidence item, the curator replies, either side resolves (#366).
- `GET /curations/{id}/diff` compares evidence with the last submission; the review screen shows field-level before and after, or all items for a first review (#366, #371, #382).
- Approve checklist (SOP items, replication for Definitive), blocked until every item is accepted or its queries resolved; the request-changes dialog is prefilled with open queries (#371).
- Review queue: one filtered list for rows and page count, "Assigned to me" toggle, plain empty state (#371).
- Reject and request changes return the curation to its curator as an editable draft; resubmission starts a new review round (#360).
- One shared 2000-character limit for queries and feedback, with counters (#383).

## My work and navigation

- `GET /me/work` returns the caller's items grouped as needs you / waiting / done, each with next action and link (#338).
- `/my-work` replaces the Dashboard; `/` lands signed-in users there and `/dashboard` redirects (#359).
- Precurations to review link to the pre-filtered review queue; drafts sent back read "Address review feedback"; scope display names instead of slugs (#387).
- Navigation is role-aware: Review shows only for scope reviewers and admins and platform admins, Assignments only for platform admins (#387).
- The My work badge was keyed to the wrong route and never showed (#372).

## Security and RLS

- Capability checks in one place (`core/capabilities.py`); curation PUT now requires curator or admin (reviewers and viewers were let through); nobody approves their own precuration, platform admins included (#340).
- Only scope reviewers and scope admins can review; curators and viewers can no longer be assigned as reviewer or submit a review, and platform admins have no review bypass (#360).
- Scope reviewers and admins may update work by others while it is under review and create the curation an approval produces; a database guard stops them changing evidence, gene, scope or authorship. RLS denials during approve or a transition return 403, not 500 (#388).
- Gene creation needs a platform admin or a curator or scope admin; stored gene data is re-fetched from HGNC rather than taken from the client (#365).
- One visibility rule (public active scope or accepted membership, no platform-admin bypass) for the old catalogue, the matrix, `GET /search`, gene scopes and gene summaries; private scopes no longer change what non-members see (#347, #350, #369).
- LIKE wildcards in searches are escaped; NUL and over-long input return 422 (#349, #369).
- The single gene page `GET /genes/{id}` is public and anonymous responses carry no assignment details (#382).

## Backend hygiene

- `models.py` split by domain behind a re-export shim (#344).
- Pydantic v2 config, timezone-aware timestamps, lifespan handler, CORS headers on 500 responses (#336, #342).
- passlib replaced by bcrypt; async test leaks and the IntersectionObserver test flake fixed (#343, #346).
- Terminal `archived` workflow stage (migration 036); soft delete and superseding set it (#353, #372).
- v0.4.1 maintenance: zero lint warnings, formatter is a no-op (#328). Planning docs and sprint scripts (#335).

## Fixes

- Missing `publications` table (migration 039): `POST /publications/validate` returned 500 on a fresh database (#384).
- Validating evidence against a sectioned schema returned 500 (#384).
- Dashboard count (#342); `in_review` status shown in the scope gene map (#345).
- An expired access token is refreshed before the first requests after a reload (#382).
- Gene intake: one invalid token no longer rejects the whole list (#383); readable 422 messages in review dialogs and intake (#383).
- Command palette shows a failed search as an error, not also "No results" (#383).
- Create-scope name validation and slugs for non-ASCII letters; long scope descriptions wrap on phones (#387).
- Home page title reads "Gene Curator" (#382).

## Upgrading

- **Run `make db-migrate`** before restarting the backend. New migrations:
  - `036_archived_workflow_stage.sql` (#353)
  - `037_review_item_comments.sql` (#366)
  - `038_reviewer_update_policies.sql` (#388)
  - `039_publications_table.sql` (#384)
  - `040_precuration_lock_version.sql` (#385)
- **API change: `lock_version` is required** on curation and precuration updates (PUT and draft saves). Send the version you loaded; a missing version returns 422, a stale one 409 with the current version (#385).
- **API change: reviewing needs a scope reviewer or scope admin membership**; curators and platform admins without one get 403 (#360).
- Gene creation (`POST /genes`, `POST /genes/bulk`) needs curator or scope admin, and IDs HGNC cannot confirm are rejected (#365).
- `/dashboard` redirects to `/my-work` (#359).
- Coming from v0.3.x: follow the v0.4.0 upgrade notes first.
