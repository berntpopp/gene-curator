# v0.13.0

Wave 11 release: ClinGen adoption and provenance for KGDB. Curators adopt ClinGen
classifications in bulk (a second person confirms them), evidence rows carry VA-Spec sources
and AI-agent attribution, the export gains `adoption`, `contributions`, `evidence_lines` and
`synopsis`, and an example export page is generated from the real serializer. Also: a
capability matrix as data with scope-owned methodologies and allowed workflow pairs, moving
curations to a newer methodology version, table builders with draft diagnostics, the approved
KGDB susceptibility tiering, SOP v11 family-aware segregation scoring and a saved, reorderable
catalogue view.

Every item cites a merged PR, checked against `gh pr view` and the merged code on 2026-10-31
(merged since v0.12.0: #592, #594, #598–#606).

## Highlights

- **ClinGen adoption (#105).** `POST /api/v1/curations/clingen-adoptions` (`dry_run`
  supported; MCP `adopt_clingen_classifications` on `/mcp`) takes rows of entity (gene, scope,
  workflow pair, MONDO, MOI) plus the GeneFoundry `clingen_get_gene_validity` record verbatim.
  Gene HGNC, MONDO and MOI must match the entity and the class must be one of the schema's; any
  invalid row is a 422 with nothing written; an entity with an open curation is refused; the
  same `cggv_id` again is `unchanged`. Each curation starts in review with the ClinGen class and
  an automatic review comment; the adopter cannot approve it (403), another reviewer does. An
  *Adopted from ClinGen* badge links the record. Gene Curator never fetches it.
  [#598](https://github.com/berntpopp/gene-curator/pull/598)
- **Provenance and AI agents (#593).** A `source` field type (PMID, DOI, ClinVar, ClinGen
  allele/validity, URL, database; id checked per kind) and a `direction` cell in both bundles.
  The 8 MCP evidence write tools take an optional `agent` block `{model, agent, tools_used}`,
  stamped into `audit_log.change_metadata.agent` with `actedOnBehalfOf` the token's user
  (migration 080); approvals and reviews refuse it, and 4-eyes applies to the person. Row
  authorship lives in `curations.row_provenance` beside the evidence and shows on evidence rows
  and in a new History panel. [#602](https://github.com/berntpopp/gene-curator/pull/602)
- **Entity synopsis.** `ui_configuration.synopsis_field` names one text field (checked at
  publish); it is exported and shown on the gene page and curation detail with evidence
  visibility. The KGDB bundle and the new ClinGen bundle (`docs/schemas/clingen/`) use
  `evidence_summary`. [#602](https://github.com/berntpopp/gene-curator/pull/602)
- **Example export page (#596).** A test writes `docs/examples/export-page.json` with the real
  serializer and validates it against `docs/examples/export-page.schema.json`; both fail when
  stale. [#602](https://github.com/berntpopp/gene-curator/pull/602)
- **Capability matrix and scope-owned configuration (#284).** `role_capabilities` (migration
  082) holds the role-to-capability matrix; the API's `require(...)` and the RLS helpers read
  the same rows. `owner_scope_id` on schemas, workflow pairs and methodology versions lets scope
  admins create, derive, edit and publish methodologies and workflows for their own scope
  (global ones stay platform-admin only and read-only to them). `PUT /scopes/{id}/workflow-pairs`
  and an *Other allowed workflows* scope setting list the pairs a scope may use; pickers show
  only those. Configuration changes are audited.
  [#604](https://github.com/berntpopp/gene-curator/pull/604)
- **Move to version (#591).** `POST /api/v1/schemas/curation-schemas/{id}/move-to-version`
  (dry run by default; MCP `move_to_version` on `/mcp/full`) and a dialog in Schema Management
  re-pin a schema's curations to its latest version in one audited transaction: gone fields are
  dropped (kept in the audit log), rows are rescored; an active curation whose class changes
  reopens in review, one missing a new required field goes to draft. Migration 078 allows only a
  forward move by a platform admin; the mover cannot review the moved curation.
  [#600](https://github.com/berntpopp/gene-curator/pull/600)
- **Table builders (#282).** A Workflow tab edits stages; object fields and nested groups,
  `and` row-rule conditions and point-model test evidence (in the real form) get builders. The
  unsaved draft is checked through `POST /validation/validate-schema` with inline problems and
  tab badges. The import dry run lists fields added, removed or changed per schema.
  `required_when` targets are cross-checked and url `max_length` is enforced. Migration 081
  adds `curation_schemas.lock_version`; a stale save is 409 and the editor keeps the draft.
  [#599](https://github.com/berntpopp/gene-curator/pull/599)
- **KGDB susceptibility tiering.** The approved tiering (kidney-genetics-db#473): points by
  study size (1/2/3), 0 when not significant after correction, included in a meta-analysis or
  protective; a new `meets_very_strong` gates Established; association cap 9, total 11, bands
  on the association section only (`section_min`); new class `refuted`. No longer provisional.
  Re-import writes a changed schema description, and `band_margin` respects `section_min`.
  [#603](https://github.com/berntpopp/gene-curator/pull/603)
- **SOP v11 segregation (#447).** Point-model rule `segregation_sop11` scores a family table
  (AD/XL and AR LOD formulas, method, exclusions, Figure 6 bands, max 3) with a rationale per
  family in the trace; a curator override needs a rationale and raises
  `review_flags.segregation_override`. The ClinGen bundle gets its next methodology version;
  older pins are not rescored. See `docs/POINT-MODEL.md`.
  [#606](https://github.com/berntpopp/gene-curator/pull/606)
- **Catalogue view (#276).** Scope columns are reordered by drag or arrow buttons, a *With
  results* preset picks scopes with an active curation, and the view is saved per user
  (`GET/PUT /api/v1/me/views/catalogue`, migration 084). A blank verdict counts as unclassified.
  [#605](https://github.com/berntpopp/gene-curator/pull/605)

## Breaking changes

- 4-eyes refusals are 403 (the actor may not act) and workflow-state refusals 409 (wrong state,
  review completed, `Invalid transition`), no longer 400.
  [#592](https://github.com/berntpopp/gene-curator/pull/592)
- A scope with a default pair or an allowed list refuses precuration, curation and adoption in
  any other pair (422). Migration 082 does not backfill the list: add a scope's other pairs
  under scope settings, or re-import its methodology bundle (a bundle's other pairs become
  allowed in its default scope). [#604](https://github.com/berntpopp/gene-curator/pull/604)
- Schema saves require `lock_version`; a stale one is 409.
  [#599](https://github.com/berntpopp/gene-curator/pull/599)
- Publishing a schema whose `required_when` names no field, or whose `synopsis_field` is not a
  text field, now fails. [#599](https://github.com/berntpopp/gene-curator/pull/599),
  [#602](https://github.com/berntpopp/gene-curator/pull/602)
- Text `min_length` counts the trimmed value.
  [#601](https://github.com/berntpopp/gene-curator/pull/601)
- The public summary of a known gene with no public curation is 200 `null`, not 404.
  [#601](https://github.com/berntpopp/gene-curator/pull/601)

## Downstream (KGDB) contract changes

Export stays `export_version` `"1"`; all changes are added fields (mapping in
`docs/EXPORT.md`).

- `adoption`: `null` unless the curation adopted a ClinGen classification; otherwise a
  VA-Spec style statement with a `reportedIn` Document (permalink) and contributions (GCEP
  interpreter, curator, approver). [#598](https://github.com/berntpopp/gene-curator/pull/598)
- `contributions[]` per curation and `evidence_lines[]` per evidence row (sources, direction,
  row contributions), VA-Spec 1.0 / SEPIO names: curator SEPIO:0000156, assessor
  SEPIO:0000154 (only for approving reviews the caller may see), approver SEPIO:0000155,
  interpreter SEPIO:0000331, publisher SEPIO-CG:97010. An MCP agent appears as a `software`
  contributor (always `curator`) with `actedOnBehalfOf` the person. `evidence_lines` follows
  `evidence` visibility. [#602](https://github.com/berntpopp/gene-curator/pull/602)
- `synopsis`: the text of the methodology's synopsis field, same visibility as evidence.
  [#602](https://github.com/berntpopp/gene-curator/pull/602)
- Contribution `date` is ISO 8601 UTC with a `Z` suffix like the other export timestamps; a
  bare source date is midnight UTC. [#602](https://github.com/berntpopp/gene-curator/pull/602)
- Anonymous callers now get `methodology.version` (085); archived rows stay member-only.
  [#601](https://github.com/berntpopp/gene-curator/pull/601)
- Susceptibility export mapping adds `refuted` → KGDB `Refuted association`; 4 frozen field
  ids added, none removed or renamed.
  [#603](https://github.com/berntpopp/gene-curator/pull/603)

## Known limits

- Adoption copies the ClinGen class only; point values must be re-scored manually.
  [#598](https://github.com/berntpopp/gene-curator/pull/598)
- The agent block is reported by the client and not verified.
  [#602](https://github.com/berntpopp/gene-curator/pull/602)
- The form/workflow canvas was dropped (owner decision); builders are tables.
  [#599](https://github.com/berntpopp/gene-curator/pull/599)
- Field renames and moves between methodologies are not handled by *Move to version*.
  [#600](https://github.com/berntpopp/gene-curator/pull/600)
- Capability audit rows are written after the change commits (queued for the polish PR).
  [#604](https://github.com/berntpopp/gene-curator/pull/604)
