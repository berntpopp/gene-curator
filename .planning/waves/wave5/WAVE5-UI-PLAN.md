## MONDO primary-source evidence and selected filter

**Authoritative classification:** [Mondo's own QC rules](https://mondo.readthedocs.io/en/latest/editors-guide/quality-control-tests/) distinguish the human-disease branch `MONDO:0700096` from non-human animal disease `MONDO:0005583` using transitive rdfs:subClassOf. The same documentation's cross-species match QC checks ancestry under the human branch. [Mondo's hereditary pattern](https://mondo.readthedocs.io/en/latest/editors-guide/patterns/hereditary/) uses human disease as its disease input. No reliable human-only selection is obtained by matching words like canine, dog or animal.

**Upstream API capability:** [official OLS V2EntityController](https://raw.githubusercontent.com/EBISPOT/ols4/dev/backend/src/main/java/uk/ac/ebi/spot/ols/controller/api/v2/V2EntityController.java) explicitly accepts arbitrary indexed fields as query-parameter filters. Swagger hides those dynamic fields; their absence from the named parameter list does not mean unsupported. [Official OLS API docs](https://www.ebi.ac.uk/ols4/api-docs) and [live OpenAPI](https://www.ebi.ac.uk/ols4/v3/api-docs) confirm the existing endpoint. Returned entities include `directAncestor` as full IRI strings (all ancestors through is-a relations, not only immediate parents), separate `directParent`, `hierarchicalAncestor`, `type`, `isObsolete`, `curie`, label and existing parser fields.

**Smallest exact #437 acceptance implementation:** keep current `GET https://www.ebi.ac.uk/ols4/api/v2/entities` parameters and add `directAncestor=http://purl.obolibrary.org/obo/MONDO_0700096`; optionally `type=class` if needed to constrain entity kind. Filtering occurs before pagination, preserving useful result limits and accurate totalElements. Do not fetch each candidate's ancestors separately, download an ontology or filter by xref/name. Retain `includeObsoleteEntities=false` and ontologyId=mondo.

**Read-only live probes completed:** unfiltered `canine` returned 71 hits, including MONDO:0025397 canine distemper; human-ancestor-filtered `canine` returned 5 human results, including MONDO:0007258 absence of upper permanent canine teeth and MONDO:0024893 toxocara canis infection. Filtered `Marfan` returned 22 hits including MONDO:0007947; every returned hit had the human root in directAncestor. Filtered diabetes returned 181 rather than 260 hits. These are dated observations, not stable test counts; mocked tests assert semantic membership, not today's counts. Human-root live entity itself is defined via in-taxon Homo sapiens and present-in-taxon annotation, supporting branch meaning; do not require the annotation on each descendant because inheritance is represented by ancestry.

**Boundary/tradeoff:** human disease ancestry excludes some human susceptibility entities outside that branch: MONDO:0009100 (`type 1 diabetes mellitus 1`) is currently under inherited disease susceptibility/MONDO:0042489, not human disease. This follows the literal human-disease-only acceptance but narrows autocomplete beyond animal removal. Preserve every already-stored/selected ID and display value; apply filter to suggestions only, no migration or save-time revalidation. State this limitation in PR/release notes; no automatic remapping.

Claude Code CLI **claude-opus-5-5** initially preferred animal-branch exclusion to retain susceptibility targets. Root selected that preference only if it can be expressed authoritatively server-side in the same request; otherwise the positive human branch is the authorized fallback. Further primary-source investigation settled this: [OLS DynamicFilterParser](https://raw.githubusercontent.com/EBISPOT/ols4/dev/backend/src/main/java/uk/ac/ebi/spot/ols/repository/helpers/DynamicFilterParser.java) sends every dynamic field to positive addFilter, and [EntityRepository](https://raw.githubusercontent.com/EBISPOT/ols4/dev/backend/src/main/java/uk/ac/ebi/spot/ols/repository/EntityRepository.java) exposes exclusion only for ontology IDs. Live probes using `directAncestor=!IRI`, `-directAncestor=IRI` and `excludeDirectAncestor=IRI` all returned zero, not non-animal results. Do not use them. **Final selection: the verified positive human-disease ancestor filter**, document susceptibility narrowing, preserve existing selections, and avoid local pagination workarounds/N+1 calls. Follow-up Opus 5.5 consultation confirmed this fallback after receiving the verified source/probe findings. Its generic suggestion to ask the owner again does not apply: the owner forbade further questions and root already authorized this fallback. Add the established `shortcut: <limit>, <when to upgrade>` comment for susceptibility narrowing, and a concise user-facing note; no new option or approval gate.
