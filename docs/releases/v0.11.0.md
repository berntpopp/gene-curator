# v0.11.0

Wave 9 release: a curator classification next to the computed one, a relationship type
(Mendelian or susceptibility) with a schema-defined classification vocabulary, `llm_share`
fields and an opt-in second view on submit, point-model section minimums and per-variant caps,
and a per-scope option that only a signed-in person may approve.

Every item cites a merged PR, checked against `gh pr view` and the merged code on 2026-10-30
(merged since v0.10.1: #551–#555, #561, #562).

## Highlights

- **Curator and final classification (#533).** Migration 071 adds nullable
  `curations.curator_classification` and `curator_classification_rationale` (audited by the
  row trigger; reviewers cannot change them). `final_classification` is the curator's class
  if set, else the computed verdict, and the catalogue, gene summary, search, My work, scope
  verdict counts and export use it; `computed_verdict` is still returned beside it. Sending a
  curation to review with a class that differs from the computed one and no rationale returns
  422. The form defaults to the calculated class and asks for a rationale when it differs;
  the approve dialog shows both. [#555](https://github.com/berntpopp/gene-curator/pull/555)
- **Relationship type and classification vocabulary (#539).** ClinGen Precuration gets a
  Relationship type field (`mendelian` or `susceptibility`, default `mendelian`), published as
  a new methodology version by migration 072. Only susceptibility entities get a
  `|SUSCEPTIBILITY` suffix on `entity_key`, so existing keys are unchanged and Mendelian and
  susceptibility curations of one gene, MONDO id and MOI coexist. `relationship_type` is on
  precurations, curation detail, catalogue, gene summary and export. Saving a curation whose
  evidence names another MONDO id, MOI or relationship type than its entity returns 409.
  Schemas can declare `scoring_configuration.classifications: [{key, label, order, tone}]`;
  labels, colours and sort order follow it, and without one the ClinGen list applies. The
  catalogue matrix filters by `classification=`.
  [#554](https://github.com/berntpopp/gene-curator/pull/554)
- **LLM sharing for custom schemas (#534).** Fields flagged `llm_share: true` in the
  curation's methodology version are sent with the seeded evidence keys; curator judgement
  keys never are. Schema validation rejects `llm_share` on a judgement key or a non-boolean
  flag, and warns about fields a run would drop.
  [#553](https://github.com/berntpopp/gene-curator/pull/553)
- **Second view on submit (#464).** Scope setting `auto_second_view_on_submit` (migration 073,
  off by default) queues the LLM second view after a successful curation submit, under the
  existing caps. It never fails the submit, a pending run is not queued twice, and the run
  belongs to the admin who last saved the scope's LLM settings.
  [#553](https://github.com/berntpopp/gene-curator/pull/553)
- **Point-model section minimums and group caps (#556, #557).** A band can set
  `section_min: {<section>: <number>}` and matches only when every listed section reaches it;
  unknown band keys are now rejected at publish. A type can set `group_by` and `group_cap` to
  cap points per group value (for example per variant); capped groups are listed in
  `trace.capped_groups`. ClinGen scores are unchanged.
  [#561](https://github.com/berntpopp/gene-curator/pull/561)
- **Approvals only from a signed-in person (#560).** Scope setting
  `approvals_require_session` (migration 074, off by default). When on, a personal access
  token, MCP OAuth token or MCP call gets 403 on every approving action (precuration approve,
  review approve, moves to active and precuration to curation, also in bulk), and on adding,
  inviting or promoting members to curator, reviewer or admin. Comments, change requests,
  rejections and drafts still work. Only scope admins change it, from a signed-in session.
  [#562](https://github.com/berntpopp/gene-curator/pull/562)

## Breaking changes

- A curation save or create whose evidence moves it to another entity (MONDO id, MOI or
  relationship type) returns 409 instead of saving.
  [#554](https://github.com/berntpopp/gene-curator/pull/554)
- Point-model bands with keys other than `class`, `min`, `requires`, `description` and
  `section_min` no longer publish. [#561](https://github.com/berntpopp/gene-curator/pull/561)
- <!-- TODO(release): re-check after #563 merges -->
  `GET/PUT /workflow/configuration/{scope_id}` are removed. They were stubs (GET hard-coded,
  PUT saved nothing) with no frontend or MCP caller.
  [#563](https://github.com/berntpopp/gene-curator/pull/563)

## Fixes

- Soft delete archives the curation's active pointer (reason "Curation deleted"), so views,
  the catalogue and gene summaries no longer show a deleted curation as current; the export
  keeps it as an archived row. [#551](https://github.com/berntpopp/gene-curator/pull/551)
- The entity chooser lists legacy open curations without a precuration link, and a required
  url field of only spaces now fails validation.
  [#551](https://github.com/berntpopp/gene-curator/pull/551)
- PMID, ontology, gene verification and add-genes lookups no longer call `asyncio.run` on
  sync paths, so they work when the calling thread already runs an event loop.
  [#552](https://github.com/berntpopp/gene-curator/pull/552)
- README documents rate limiting (off by default, on in `docker-compose.prod.yml`).
  [#551](https://github.com/berntpopp/gene-curator/pull/551)

## Upgrading

1. Upgrade through the [v0.10.1 instructions](v0.10.1.md#upgrading) first.
2. Run `make db-migrate` before restarting the backend. It applies 071 (curator
   classification), 072 (relationship type; recreates the entity-key column and open-draft
   index once), 073 (`auto_second_view_on_submit`), 074 (`approvals_require_session`) and 075
   (Standard_Precuration relationship type). Both scope settings default to off, so
   behaviour does not change until a scope admin turns them on.
   [#555](https://github.com/berntpopp/gene-curator/pull/555),
   [#554](https://github.com/berntpopp/gene-curator/pull/554),
   [#553](https://github.com/berntpopp/gene-curator/pull/553),
   [#562](https://github.com/berntpopp/gene-curator/pull/562)
3. Custom schemas: flag fields an LLM run may see with `"llm_share": true` in
   `field_definitions`; nothing is needed for seeded schemas.
   [#553](https://github.com/berntpopp/gene-curator/pull/553)
4. Callers of `/workflow/configuration/{scope_id}` must drop them (none known).

## Downstream (KGDB) contract changes

Export stays `export_version` `"1"`; all changes are added fields or new values.

- `entity_key` is `MONDO|MOI` plus `|SUSCEPTIBILITY` for susceptibility entities. Do not split
  it on `|` to get the MOI; use `moi_hpo_id` and `relationship_type`.
  [#554](https://github.com/berntpopp/gene-curator/pull/554)
- New fields: `relationship_type` (`mendelian` or `susceptibility`)
  [#554](https://github.com/berntpopp/gene-curator/pull/554); `final_classification` (curator
  class, else computed) and `curator_classification_rationale`
  [#555](https://github.com/berntpopp/gene-curator/pull/555); `archive_reason`
  [#551](https://github.com/berntpopp/gene-curator/pull/551). The export has no separate
  `curator_classification` field; a differing `final_classification` and `computed_verdict`
  mark an override.
- Deleted curations arrive as `status: archived` with `archive_reason: "Curation deleted"` for
  members, and `updated_since` returns them; retract them. Anonymous callers see active rows
  only. [#551](https://github.com/berntpopp/gene-curator/pull/551)
- Compare classes by key: lowercase, spaces and hyphens as underscores (`no_known...` as
  `no_known`). Schema vocabularies may add classes beyond the ClinGen list, so do not reject
  unknown classes. [#554](https://github.com/berntpopp/gene-curator/pull/554),
  [#555](https://github.com/berntpopp/gene-curator/pull/555)

## Known limits

- Anonymous export callers still get `methodology.version = null`; fixing it needs an anon read
  policy on `methodology_versions`. [#551](https://github.com/berntpopp/gene-curator/pull/551)
- The MCP server instructions are 4,093 characters, at the 4,096-character limit where Claude
  Code cuts them; new text there needs something removed.
- Catalogue matrix class labels come from each scope's current schema, not from the
  methodology version a curation was scored with.
