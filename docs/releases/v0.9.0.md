# v0.9.0

Wave 7 release: an authenticated MCP server for AI agents (personal access tokens, a lean
curation core on `/mcp` and every operation on `/mcp/full`), an LLM configuration console, save
and submit validation, a cited-evidence scoring policy, leaner API responses, rate limiting and
the Wave 6 follow-ups.

Every item cites a merged PR, checked against `gh pr view` and the merged code on 2026-10-28.
PRs merged after #520 go in the section they fit and, if they change an upgrade step or break a
client, under [Upgrading](#upgrading) too.

## Highlights

- **MCP server with personal access tokens.** Personal access tokens (`gc_pat_...`) authenticate
  REST and MCP clients. Only a sha256 hash is stored, the plaintext is shown once, expiry is
  required (at most 365 days, the UI defaults to 90), a read-only token gets 403 on every write,
  and a token cannot create tokens or change accounts, emails, roles or passwords. Tokens are
  managed under `/profile/tokens`. Migration 056. [#494](https://github.com/berntpopp/gene-curator/pull/494)
- The MCP server is built from the API's own OpenAPI and calls the real routers in process, so
  every tool runs through the same auth, capability checks, 4-eyes rule, `lock_version` and RLS.
  It accepts only personal access tokens, not JWTs. Audit rows record channel `mcp` and the token
  name (migration 059), and these headers are stripped from network requests so they cannot be
  spoofed. Tool errors use closed codes (`invalid_input`, `forbidden`, `conflict`, ...).
  Setup: [docs/MCP_CONNECTION_GUIDE.md](../MCP_CONNECTION_GUIDE.md).
  [#498](https://github.com/berntpopp/gene-curator/pull/498)
- `/mcp` serves a curation core of 47 tools: pipeline setup, curating a gene end to end,
  reviewing and validating entries. `/mcp/full` serves every operation (REST is unchanged).
  Research (papers, genotypes, ontology lookups) goes through a literature MCP such as
  GeneFoundry; saves still check every PMID and MONDO, OMIM and HPO ID. Admin-only tools are
  hidden from non-admins. Results drop empty values, and a result over about 8k tokens returns
  `response_too_large` with a hint on how to narrow the request.
  [#508](https://github.com/berntpopp/gene-curator/pull/508),
  [#509](https://github.com/berntpopp/gene-curator/pull/509),
  [#519](https://github.com/berntpopp/gene-curator/pull/519)
- The server sends instructions (workflow map, scope roles, 4-eyes rule, the shortcuts below),
  tool descriptions are short, and each result goes out once as JSON text. Tool errors end with
  a `next:` hint, and `not_found` hints name the tool that fixes it.
  [#504](https://github.com/berntpopp/gene-curator/pull/504),
  [#506](https://github.com/berntpopp/gene-curator/pull/506),
  [#512](https://github.com/berntpopp/gene-curator/pull/512),
  [#514](https://github.com/berntpopp/gene-curator/pull/514),
  [#517](https://github.com/berntpopp/gene-curator/pull/517)
- MCP arguments are checked before the call: unknown names get a did-you-mean, missing required
  arguments and type or bound violations name the field and the bound.
  [#512](https://github.com/berntpopp/gene-curator/pull/512)
- Fewer round trips for agents: `scope_name` works wherever `scope_id` did; submit and the
  transition into review take `reviewer_id` or `reviewer_email`, assign in the same transaction
  and echo `assigned_reviewer {id, name}`; `add_genes_to_scope` adds genes by symbol, alias or
  HGNC id; one `read_curation_for_review` call returns everything a reviewer needs.
  [#510](https://github.com/berntpopp/gene-curator/pull/510),
  [#513](https://github.com/berntpopp/gene-curator/pull/513)
- `get_curation_schema(path=)` returns only one evidence field as
  `{schema_id, path, field, validation_rules, point_ranges}` (about 1 KB for one table);
  `calculate_score` sends the score trace once.
  [#512](https://github.com/berntpopp/gene-curator/pull/512),
  [#514](https://github.com/berntpopp/gene-curator/pull/514),
  [#517](https://github.com/berntpopp/gene-curator/pull/517)
- **LLM configuration console.** `/admin/llm` (platform admins) manages providers with
  write-only keys, pinned models with prices, versioned prompts (published versions immutable,
  diff, publish) and usage and run logs. Scope admins opt in per scope under Settings and set
  monthly caps. [#491](https://github.com/berntpopp/gene-curator/pull/491),
  [#497](https://github.com/berntpopp/gene-curator/pull/497),
  [#499](https://github.com/berntpopp/gene-curator/pull/499)
- Keys are encrypted with their own key ring (`LLM_CREDENTIAL_KEYS`), separate from
  `SECRET_KEY`, and `make rotate-llm-keys` re-encrypts them. Provider URLs pass an SSRF check
  on every call. Adapters cover Anthropic and OpenAI-compatible APIs; `MockProvider` runs every
  test, and `make llm-eval` (opt-in, never in CI) runs the golden set against a real provider.
  Migration 057. [#491](https://github.com/berntpopp/gene-curator/pull/491),
  [#497](https://github.com/berntpopp/gene-curator/pull/497),
  [#500](https://github.com/berntpopp/gene-curator/pull/500)
- A background worker (`LLM_WORKER_ENABLED`) runs queued runs as the run's creator, so RLS
  applies. Enqueue checks opt-in, enabled model and provider, a published prompt and the caps,
  and fails closed. Scope admins can preview exactly what would be sent
  (`GET /scopes/{sid}/curations/{cid}/llm-preview`); only allowlisted curation fields and public
  IDs are sent, never user names or emails. Prompts have a test-run button. Migration 060.
  [#500](https://github.com/berntpopp/gene-curator/pull/500)

## Scoring and validation

- **Cited-evidence scoring policy.** A row that scores needs a PMID PubMed knows; a case-level
  row also needs a real variant (HGVS, rsID or genomic coordinate). GenCC rows with points need
  a PMID too. Other rows score 0 and are listed in `breakdown.excluded` with `no_pmid`,
  `unknown_pmid`, `no_variant` or `placeholder_variant`, wherever scores are computed (save,
  preview, calculate, recompute, methodology version tests). Excluded rows keep their position,
  so later row paths no longer shift. [#507](https://github.com/berntpopp/gene-curator/pull/507),
  [#511](https://github.com/berntpopp/gene-curator/pull/511)
- **`score_status` decides what counts.** An SOP v11 case row scores only when its
  `score_status` is `score`; `review` and `contradicts` score 0 (`not_scored`), a blank status
  scores 0 (`missing_status`) and warns on save. [#515](https://github.com/berntpopp/gene-curator/pull/515)
- The review gate (submit, workflow and bulk paths into review) refuses scored rows that would
  be excluded and rows with points but a blank `score_status`, naming the field path. Rows
  marked `review` are not refused, and drafts never block.
  [#511](https://github.com/berntpopp/gene-curator/pull/511),
  [#515](https://github.com/berntpopp/gene-curator/pull/515)
- **Save validation.** Draft saves never block: they return `warnings` for malformed or unknown
  PMIDs and MONDO, OMIM and HPO IDs (an unreachable upstream marks an ID unverified). An unknown
  PMID's warning says the row scores 0 and submit will refuse it. Curation and precuration
  submit return 422 with `detail.errors[] = {path, message}`; curation submit also refuses
  unknown ontology IDs. `merge: true` on save_draft and `PUT /curations/{id}` applies
  `evidence_data` as an RFC 7396 merge patch, with the same `lock_version` check.
  [#507](https://github.com/berntpopp/gene-curator/pull/507),
  [#520](https://github.com/berntpopp/gene-curator/pull/520)
- `create_precuration` returns the `required_fields` still empty (path, type, allowed values);
  the precuration submit 422 lists the same for the missing ones.
  [#520](https://github.com/berntpopp/gene-curator/pull/520)
- Reviewer warnings with paths: placeholder variants, misfiled variant types, cohort proband
  labels, one PMID used for 3+ probands, a PMID in a free-text field, unknown PMIDs cited in free
  text, an `evidence_summary` claiming a different total, experimental or model rows that look
  like a patient, and a Definitive hint once genetic evidence reaches 12 points without
  replication over time. Save and submit results collapse repeated warnings to one per message
  with a row count and the first 3 paths.
  [#511](https://github.com/berntpopp/gene-curator/pull/511),
  [#515](https://github.com/berntpopp/gene-curator/pull/515),
  [#516](https://github.com/berntpopp/gene-curator/pull/516),
  [#520](https://github.com/berntpopp/gene-curator/pull/520)
- Evidence-item create and update validate the item against the curation's schema (422 for an
  unknown category, column or PMID) and say that items are not scored.
  [#501](https://github.com/berntpopp/gene-curator/pull/501)

## Workflow and review

- A curator can route a submitted precuration to a reviewer, who approves it. A curator
  assigning a reviewer to a submitted curation no longer gets 500 (migration 061 adds the RLS
  insert policy; other RLS denials return 403). [#503](https://github.com/berntpopp/gene-curator/pull/503)
- `get_workflow_state` lists only the moves the caller may make and gives a reason for each
  blocked one; a stale save's 409 names who saved, when and which keys changed;
  `curation_diff?baseline=submitted|active|<audit id>` returns `changed`.
  [#506](https://github.com/berntpopp/gene-curator/pull/506)
- `curation_diff` also accepts `baseline=previous_submission`, and the workflow audit trail
  lists every submission and review decision with the `audit_id` of its evidence snapshot.
  [#511](https://github.com/berntpopp/gene-curator/pull/511)
- `read_curation_for_review` drops zero-point trace rows, returns `first_submission: true`
  instead of an all-"added" diff, and on a resubmission adds `previous_reviews` and
  `open_item_comments`. It shows warnings once, and lists previous reviews after a request for
  changes (they were missing). [#513](https://github.com/berntpopp/gene-curator/pull/513),
  [#518](https://github.com/berntpopp/gene-curator/pull/518)
- While a curation is in review, `get_curation` lists `assigned_reviewers` (id, name).
  `create_curation` and the full `update_curation` response carry `curation_schema_id`.
  [#517](https://github.com/berntpopp/gene-curator/pull/517),
  [#520](https://github.com/berntpopp/gene-curator/pull/520)
- Workflow pairs have a default (migration 062, seeded on ClinGen SOP v11); `create_scope` uses
  it when no pair is given. New `POST /scopes/{id}/members` lets a platform or scope admin add an
  existing user as an accepted member; invitations keep the consent flow.
  [#505](https://github.com/berntpopp/gene-curator/pull/505)
- `invite_member` no longer claims to auto-accept: invitations stay pending until accepted.
  Review assignments carry `gene_symbol` and `scope_name`; `list_curations` filters by both.
  `GET /schemas/curation-schemas/{id}?compact=true` returns a smaller schema (37 KB to 15 KB on
  ClinGen SOP v11). [#502](https://github.com/berntpopp/gene-curator/pull/502)
- `create_precuration` defaults its schema from the scope's workflow pair; `get_curation` and
  `get_scope` carry the schema ids. [#506](https://github.com/berntpopp/gene-curator/pull/506)

## Interface

- My work and the review queue use the shared data table with search, filters, sort, page and
  density in the URL; hidden columns are remembered per browser. My work rows show their age.
  Enter in the command palette opens the first result once it arrives. The score panel lists
  rows the engine flags. [#493](https://github.com/berntpopp/gene-curator/pull/493)
- `GET /scopes/{id}` returns `user_role`, so an outsider's dashboard no longer calls `/members`
  and gets 403. [#492](https://github.com/berntpopp/gene-curator/pull/492)

## Security

- Rate limiting: a token-bucket middleware keyed by user for valid bearer tokens, else by client
  IP, with 429 and `Retry-After`. Off in `config/api.yaml`, on in `docker-compose.prod.yml`.
  [#492](https://github.com/berntpopp/gene-curator/pull/492)
- CORS is the outermost middleware, so the early 400 (NUL in path), 414 and 429 responses carry
  CORS headers. [#492](https://github.com/berntpopp/gene-curator/pull/492)
- Changing a gene's `hgnc_id` is platform-admin only (403 otherwise).
  [#492](https://github.com/berntpopp/gene-curator/pull/492)
- Personal access tokens: hash-only storage, RLS on own rows, no delete (revoke sets
  `revoked_at`), `app_user` may update only `revoked_at`, and blocked account operations.
  [#494](https://github.com/berntpopp/gene-curator/pull/494)
- Validation errors (422) never echo the input, which may be a password: each message states
  the field, the limit and the received size (an enum error shows the received value).
  [#520](https://github.com/berntpopp/gene-curator/pull/520)
- LLM: `app_user` cannot read credential ciphertext; keys never appear in responses, stores or
  logs; prompt and output text are never logged; free-text prompt values are wrapped as
  untrusted data; every admin change writes audit_log first and fails closed (503).
  [#491](https://github.com/berntpopp/gene-curator/pull/491),
  [#497](https://github.com/berntpopp/gene-curator/pull/497),
  [#499](https://github.com/berntpopp/gene-curator/pull/499),
  [#500](https://github.com/berntpopp/gene-curator/pull/500)

## Upgrading

1. Upgrade older installations through the [v0.8.0 instructions](v0.8.0.md#upgrading) first.
2. Run `make db-migrate` to apply 056–063 before restarting the backend:
   `056_personal_access_tokens`, `057_llm_configuration`, `058_drop_gene_summaries`,
   `059_audit_log_channel`, `060_llm_runs_worker`, `061_review_assignment_policies`,
   `062_default_workflow_pair_direct_add`, `063_evidence_category_length`.
3. The database owner that runs the migrations must be a superuser or have BYPASSRLS, because
   SECURITY DEFINER functions read past FORCE RLS as that owner
   (`authenticate_personal_access_token` in 056, `llm_credential_ciphertext` in 057,
   `llm_claim_run` in 060, `is_scope_reviewer` in 061). Without it, personal access tokens and
   MCP get 401, curators cannot assign reviewers, and the LLM worker claims nothing. On managed
   Postgres (e.g. RDS) grant BYPASSRLS.
   [#494](https://github.com/berntpopp/gene-curator/pull/494),
   [#500](https://github.com/berntpopp/gene-curator/pull/500),
   [#503](https://github.com/berntpopp/gene-curator/pull/503)
4. Set `LLM_CREDENTIAL_KEYS` (JSON `{"kid": "<Fernet key>"}`) and `LLM_CREDENTIAL_ACTIVE_KID`
   (see `.env.example`); `docker-compose.prod.yml` passes both to the backend. Missing or bad
   config fails closed for LLM keys.
   [#491](https://github.com/berntpopp/gene-curator/pull/491)
5. Rate limiting is on in `docker-compose.prod.yml`. Behind a reverse proxy, set
   `FORWARDED_ALLOW_IPS` to the proxy's address only (never a Docker range) and bind
   `BACKEND_PORT` to 127.0.0.1; unset, `X-Forwarded-For` is ignored and every client shares the
   proxy's IP bucket. [#492](https://github.com/berntpopp/gene-curator/pull/492)
6. `make recompute-scores` scores legacy rows without a citation, a real variant or (SOP v11 case
   rows) a `score_status` of `score` as 0. Active and archived curations keep their result,
   logged as `kept_uncited`, until edited and resubmitted.
   [#511](https://github.com/berntpopp/gene-curator/pull/511),
   [#515](https://github.com/berntpopp/gene-curator/pull/515)
7. MCP clients connect to `/mcp` (curation core) or `/mcp/full` (every operation) with a
   personal access token; see [docs/MCP_CONNECTION_GUIDE.md](../MCP_CONNECTION_GUIDE.md).
   [#498](https://github.com/berntpopp/gene-curator/pull/498),
   [#508](https://github.com/berntpopp/gene-curator/pull/508),
   [#519](https://github.com/berntpopp/gene-curator/pull/519)

### Breaking

- **Concise REST responses.** Curation save, update and submit return id, status, stage,
  `lock_version`, total, verdict and warnings; `GET /curations/{id}` drops zero-point trace rows
  and returns the full trace only with `detail=true`; `list_scopes` returns compact rows;
  `get_curation_schemas` returns summary rows. Pass `detail=true` for the full shape. The bundled
  frontend already does. [#506](https://github.com/berntpopp/gene-curator/pull/506),
  [#518](https://github.com/berntpopp/gene-curator/pull/518)
- **`CurationDetail.calculated_score` removed.** Read `computed_scores`.
  [#502](https://github.com/berntpopp/gene-curator/pull/502)
- **Evidence-item endpoints deprecated** (all four `/curations/{id}/evidence...`): items are not
  scored. Record evidence in `evidence_data` with save_draft. Removal is planned for Wave 8.
  [#501](https://github.com/berntpopp/gene-curator/pull/501)
- **Only cited evidence scores.** A row with no PMID, an unknown or malformed PMID, a case row
  with no or a placeholder variant, or an SOP v11 case row with a blank `score_status` scores 0,
  and submit refuses it with 422. [#507](https://github.com/berntpopp/gene-curator/pull/507),
  [#511](https://github.com/berntpopp/gene-curator/pull/511),
  [#515](https://github.com/berntpopp/gene-curator/pull/515)
- **`gene_summaries` table dropped** and `POST /genes/{id}/summary/recompute` removed.
  [#495](https://github.com/berntpopp/gene-curator/pull/495)
- **`list_curations` with an unknown `scope_name`** returns 404 with suggestions instead of an
  empty list. [#510](https://github.com/berntpopp/gene-curator/pull/510)
- **Personal access tokens** expire within 365 days and cannot create tokens or change users,
  passwords or account state (403). A read-only token gets 403 on every POST, including
  read-only POSTs (search, validate, preview).
  [#494](https://github.com/berntpopp/gene-curator/pull/494)
- **MCP:** `/mcp` is the 47-tool core; agents that used lookup, notification or invitation
  tools connect to `/mcp/full`. A malformed MCP call is refused before the API's auth check.
  [#512](https://github.com/berntpopp/gene-curator/pull/512),
  [#519](https://github.com/berntpopp/gene-curator/pull/519)
- **422 messages** no longer echo input values; clients that parsed `input` from the detail get
  the field, limit and received size instead.
  [#520](https://github.com/berntpopp/gene-curator/pull/520)

## Known limits and follow-ups

- [#496](https://github.com/berntpopp/gene-curator/issues/496): score recompute skips GenCC and qualitative curations.
- Wave 8: remove the deprecated evidence-item endpoints
  ([#501](https://github.com/berntpopp/gene-curator/pull/501)); OAuth 2.1 and dynamic client
  registration for MCP, so tokens no longer go in client config
  ([#498](https://github.com/berntpopp/gene-curator/pull/498));
  LLM second view: blind skeptic review
  ([#464](https://github.com/berntpopp/gene-curator/issues/464)) and advocate vs skeptic
  ([#465](https://github.com/berntpopp/gene-curator/issues/465)).
- An agent on `/mcp` without a literature MCP cannot look up a MONDO id for a new precuration.
  [#519](https://github.com/berntpopp/gene-curator/pull/519)
- The SSRF check resolves DNS before the request and httpx resolves again, so a DNS-rebinding
  window remains. [#491](https://github.com/berntpopp/gene-curator/pull/491)
- Partial UI items still open: #277 (My work needs disease, MOI and stage from the backend), #273
  (gene hits lack classification). [#493](https://github.com/berntpopp/gene-curator/pull/493)
