# v0.12.0

Wave 10 release: KGDB readiness end to end. Schemas and point models are built in the UI
without JSON and published from there, a methodology bundle imports idempotently, point models
get native row rules, a step rule and reviewer flags, evidence tables hold lists, and the
kidney-genetics (KGDB) bundle ships ready to import. Also: evidence, scores and summary in the
export, one open precuration per disease entity, an audited disease correction, scope gene
intake with due dates, and scope roles in User Management.

Every item cites a merged PR, checked against `gh pr view` and the merged code on 2026-10-31
(merged since v0.11.0: #570–#574, #578–#587, #589).

## Highlights

- **Schema editor without JSON (#219).** The Fields tab adds, edits, reorders and removes
  sections and fields (type, required, help, choices, evidence-table columns, `show_when`,
  `llm_share`); a Preview tab renders the draft with the real form; an Advanced JSON tab covers
  all five config blocks. A rename rewrites `show_when`/`visible_when`/`required_when` and
  layout paths and warns when scoring or a published version still names the old id.
  **Publish version** shows the validator report and the impact (workflow pairs, scope
  defaults) and is blocked on errors. [#580](https://github.com/berntpopp/gene-curator/pull/580)
- **Point-model builder (#282, part).** The Scoring tab edits caps, sections, categories,
  evidence types (default, range, group cap, `require_variant`, rule), row rules, bands,
  overrides, the classification vocabulary, review flags and embedded `tests` in tables, with
  backend diagnostics on each input and a **Run tests** button using the real engine. Paths
  and conditions are picked from the schema's own fields.
  [#581](https://github.com/berntpopp/gene-curator/pull/581),
  [#587](https://github.com/berntpopp/gene-curator/pull/587)
- **Methodology import (#575).** `POST /api/v1/schemas/methodologies/import[?dry_run=true]`,
  platform admin only, takes one bundle of schemas, workflow pairs and an optional scope
  default. Unchanged content is a no-op, changed content publishes the next methodology version,
  any validator error is a 422 with nothing written. Also `import_methodology` on `/mcp/full`
  (not core `/mcp`) and an **Import methodology** button with a dry-run plan in Schema
  Management. Format: `docs/METHODOLOGY-IMPORT.md`.
  [#579](https://github.com/berntpopp/gene-curator/pull/579),
  [#581](https://github.com/berntpopp/gene-curator/pull/581)
- **Native point-model rules (#576).** `points_when` sets a row's points from its own fields
  (`in`, `gt`, `gte`, `lt`, `lte`, `present`, `and`); a 0-point rule always wins, other rules
  fill only blank points. `rule: "step"` sums a field and scores the highest step reached.
  Applied rules appear in `trace.rules_applied`. A neutral `point_model` engine alias. ClinGen
  results are unchanged (158 golden results pinned by digest).
  [#582](https://github.com/berntpopp/gene-curator/pull/582)
- **Reviewer flags (#559).** Optional `point_model.review_flags`: `band_margin`, `hotspot`
  (a recurrent variant carries most proband points) and `experimental_over_genetic`. They warn
  the reviewer and never block a save.
  [#572](https://github.com/berntpopp/gene-curator/pull/572),
  [#584](https://github.com/berntpopp/gene-curator/pull/584),
  [#585](https://github.com/berntpopp/gene-curator/pull/585)
- **List cells (#577).** Evidence-table columns of type `multiselect` and `array` hold lists;
  typed or pasted comma lists split into entries.
  [#578](https://github.com/berntpopp/gene-curator/pull/578),
  [#586](https://github.com/berntpopp/gene-curator/pull/586)
- **KGDB methodology bundle.** `docs/schemas/kidney-genetics/kgdb-methodology.json`: KGDB
  Mendelian and Susceptibility precuration and curation schemas, pairs `KGDB Mendelian`
  (default of the `kidney-genetics` scope) and `KGDB Susceptibility`, the draft-4 point model
  with native rules, a non-scoring diagnostics section and embedded scoring tests. The README
  freezes the field ids as the KGDB import contract. The susceptibility schema is provisional.
  Curators pick the pair when they start a precuration.
  [#583](https://github.com/berntpopp/gene-curator/pull/583),
  [#586](https://github.com/berntpopp/gene-curator/pull/586)
- **Export evidence, scores and summary (#558).** Export rows gain `evidence`, `scores` (with
  the per-row trace) and `summary`. Scope members always get them; others only for a public
  scope with the new scope setting `export_evidence_public` (migration 076, off by default).
  [#570](https://github.com/berntpopp/gene-curator/pull/570)
- **Precuration integrity (#567, #284 slice, #453).** One open precuration per gene, scope and
  disease entity: a duplicate create or save gets 409 naming the existing one, enforced in the
  database by migration 077. Only the creator or a scope admin archives a precuration. Scope
  admins correct a legacy disease gap with `POST /curations/{id}/disease-correction` (audited,
  reason required); the corrector cannot then approve that curation, and curation detail
  returns `corrected_disease` so the page says why.
  [#574](https://github.com/berntpopp/gene-curator/pull/574),
  [#585](https://github.com/berntpopp/gene-curator/pull/585),
  [#589](https://github.com/berntpopp/gene-curator/pull/589)
- **Scope gene intake and roles (#281, #218).** Due dates on assignments (list column, bulk bar,
  paste dialog), a curator picker in the paste dialog, and scope roles shown and granted in
  User Management (also a first scope role at user creation).
  [#573](https://github.com/berntpopp/gene-curator/pull/573),
  [#585](https://github.com/berntpopp/gene-curator/pull/585),
  [#587](https://github.com/berntpopp/gene-curator/pull/587),
  [#589](https://github.com/berntpopp/gene-curator/pull/589)

## Breaking changes

- Migration 077 stops with a list of ids when open precurations already share a disease entity;
  archive all but one per group, then re-run. It deletes nothing.
  [#585](https://github.com/berntpopp/gene-curator/pull/585)
- Publishing (and importing) a point model whose section keys, type paths, rule fields,
  override fields or `show_when`/`visible_when` targets name no field now fails, as do
  malformed `points_when`/step rules and `review_flags`. Already published versions keep
  working. [#572](https://github.com/berntpopp/gene-curator/pull/572),
  [#582](https://github.com/berntpopp/gene-curator/pull/582),
  [#586](https://github.com/berntpopp/gene-curator/pull/586)
- A second open precuration of one disease entity returns 409; `DELETE /precurations/{id}`
  returns 403 for anyone but the creator or a scope admin.
  [#574](https://github.com/berntpopp/gene-curator/pull/574)
- Submit returns 422 for non-numeric or fractional integer cells and blank required cells in
  evidence tables (`table[row].column`); a fully blank row is dropped.
  [#585](https://github.com/berntpopp/gene-curator/pull/585)
- Under the `point_model` engine a blank points cell scores the type default instead of 0
  (ClinGen keeps explicit null as 0). Results of that engine no longer carry
  `sop_version: v11`.
  [#582](https://github.com/berntpopp/gene-curator/pull/582),
  [#586](https://github.com/berntpopp/gene-curator/pull/586)
- A read-only token lists only read tools on MCP. Making a scope public while
  `export_evidence_public` is on needs a signed-in person.
  [#585](https://github.com/berntpopp/gene-curator/pull/585)

## Upgrading

1. Upgrade through the [v0.11.0 instructions](v0.11.0.md#upgrading) first.
2. Before upgrading production, run the duplicate query from migration 077 and archive all but
   one precuration per group:
   ```sql
   SELECT gene_id, scope_id, entity_key, array_agg(id ORDER BY created_at)
   FROM precurations
   WHERE entity_key <> '' AND status IN ('draft', 'submitted', 'in_review', 'rejected')
   GROUP BY 1, 2, 3 HAVING count(*) > 1;
   ```
   [#585](https://github.com/berntpopp/gene-curator/pull/585)
3. Run `make db-migrate` before restarting the backend. It applies 076
   (`export_evidence_public`, off by default) and 077 (unique open precuration per entity).
   [#570](https://github.com/berntpopp/gene-curator/pull/570),
   [#585](https://github.com/berntpopp/gene-curator/pull/585)
4. Custom schemas whose point-model paths name missing fields now fail publish; fix them in the
   schema editor (the Check list names each path) before the next publish.
   [#582](https://github.com/berntpopp/gene-curator/pull/582)
5. KGDB: import `docs/schemas/kidney-genetics/kgdb-methodology.json` as a platform admin
   (Schema Management, *Import methodology*, or the REST call in its README), dry run first.
   [#583](https://github.com/berntpopp/gene-curator/pull/583)

## Downstream (KGDB) contract changes

Export stays `export_version` `"1"`; all changes are added fields.

- New fields `evidence`, `scores` and `summary`; `null` for non-members unless the scope is
  public with `export_evidence_public` on. Use a member token.
  [#570](https://github.com/berntpopp/gene-curator/pull/570)
- `scores` carries the trace into the export
  ([#570](https://github.com/berntpopp/gene-curator/pull/570)), including `capped_groups`
  (v0.11.0, [#561](https://github.com/berntpopp/gene-curator/pull/561)) and the new
  `rules_applied` ([#582](https://github.com/berntpopp/gene-curator/pull/582));
  `scores.warnings` holds the reviewer flags
  ([#572](https://github.com/berntpopp/gene-curator/pull/572)).
- The KGDB bundle's field ids are frozen in `docs/schemas/kidney-genetics/README.md` (a test
  fails on drift), including the diagnostics section and its reshaping notes.
  [#583](https://github.com/berntpopp/gene-curator/pull/583)

## Known limits

- The KGDB susceptibility schema is provisional (tiering, a refuted class); `verified_via`,
  `detectability_note` and resource `country_or_scope` are not in KGDB's `Diagnostics`.
  Detectability `tools` are text entries, since cells cannot hold objects. URL `max_length`
  is not enforced. [#583](https://github.com/berntpopp/gene-curator/pull/583)
- The hotspot flag assumes the `group_by` field is the variant.
  [#584](https://github.com/berntpopp/gene-curator/pull/584)
- Any workflow pair can be picked at precuration start, and create accepts any schema id; no
  per-scope allowed-pairs list. [#586](https://github.com/berntpopp/gene-curator/pull/586)
- The schema editor is last writer wins and validates the saved schema, not the unsaved draft.
  Nested groups and plain objects are edited only in Advanced JSON; `and` conditions only in
  the Code view. [#580](https://github.com/berntpopp/gene-curator/pull/580),
  [#581](https://github.com/berntpopp/gene-curator/pull/581)
- The review queue's AI second view link shows for scopes with AI off (reviewers cannot read
  the scope setting). A stale stored session logs 401s on load.
  [#586](https://github.com/berntpopp/gene-curator/pull/586)
- 4-eyes refusals return 400, not 403/409 (owner decision pending).
  [#585](https://github.com/berntpopp/gene-curator/pull/585)
- The import has no per-row diff, and `required_when` targets are not cross-checked (both
  found in Wave 10 review).
- Still open: #105 (ClinGen take-over), #276 (matrix reorder and saved view), #282 (form and
  workflow builders), #284 (capability checks), #447 (family-aware segregation).
